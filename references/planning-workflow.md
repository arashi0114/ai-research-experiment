# M2 架构规划

先阅读研究描述、论文、现有文件与配置。整理任务目标、数据集和模态、模型组成、预处理与特征提取、外部权重及冻结策略、实验分支、PyTorch/Lightning 选择，以及是否有独立的核心算法。仅询问会改变当前结构的关键未知项；其余以 TODO 保留。

生成前向用户展示：模块划分、简短数据流、各模块职责、相对默认结构的新增文件及其必要性、待定设计问题。若研究确实有文本编码器、图像编码器和推荐模型，可在 models 下增加 text_encoder.py、image_encoder.py 与 recommender.py；不要预先加入 fusion、注册器或多套 trainer，除非方案确实需要。

创建时保留已有文件。新增但尚未进入编码阶段的 Python 模块只写中文 TODO。在 docs/architecture_plan.md 保存简短架构计划和待定问题。M2 的完成依据是结构与任务一致、数据流和职责清楚、没有明显多余抽象；不以提前写完训练作为完成条件。

对于现有项目，先找可复用接口和已有功能，尽量沿用命名和风格；仅追加或局部修改必要文件，不迁移目录、不重建模板、不覆盖 checkpoint、数据和结果。会导致数据丢失的操作先取得明确授权。
