# 代码规范

使用表达含义明确的英文变量、函数和类名；每个函数只负责一件事；保持控制流直接。中文注释解释设计原因、公式、约束和必要的 tensor shape/dtype/语义，不重复代码表面行为。核心算法的代码步骤能与公式或伪代码对应。

按职责分开数据、模型、训练、评估和入口；配置与实现分开。优先简单函数与稳定接口，只有状态、参数管理或框架接口需要时才使用类。默认依赖优先标准库、PyTorch、必要的 torchvision/NumPy/PyYAML；Lightning 仅按任务采用。额外依赖需说明必要性。不要默认使用 Hydra、MLflow、W&B、Ray、Dask、数据库或分布式框架。

避免无需求的抽象基类、通用工厂、注册器、插件层、多层 Manager/Controller/Service、策略模式、依赖注入、兼容分支及 PyTorch/Lightning 已有能力的重复封装。不要把全部逻辑塞入单个脚本，也不要为了形式统一强制使用类。

对明确的前置条件快速失败：必要的数据文件、配置字段、张量形状、标签范围、数据划分、checkpoint 兼容性及适用的 NaN/Inf 检查。不要使用宽泛 try-except、反复 hasattr、静默 fallback 或悄悄替换科研参数。错误应指出哪个契约条件被违反。
