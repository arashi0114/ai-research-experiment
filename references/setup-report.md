# M5 根据代码撰写实验设置报告

先确定报告对应的项目与实验入口，沿调用关系核对实际接入的数据处理、模型、损失、训练、验证/测试、checkpoint 与结果输出，再核对配置来源和覆盖顺序。不要仅因某模块存在，就写成该实验使用了它；未接入或只有 TODO 的环节分别标为未使用或未实现。只有静态代码时，报告应称为“代码定义的实验设置”；有运行记录时，区分代码允许的配置与该次运行实际生效的配置。不能执行或缺少依赖时仍可做静态分析，并说明验证范围。

默认写 Markdown 并保存为 `docs/experiment_setup_report.md`；若用户指定格式或路径、项目已有文档约定，则遵从。报告覆盖能从现有材料确认的环节：任务与输入输出、数据来源及划分、预处理与样本构造、模型结构与张量流、预训练权重及冻结策略、损失与优化、超参数和随机性、训练循环及 checkpoint 选择、验证和测试指标及聚合、结果产物及复现方式。按项目实际内容取舍，每个已实现环节用自然语言说明做了什么，并标出支持该描述的文件、函数或配置项；关键数值写明来源。可用参数表辅助阅读，但不要让表格代替流程解释。

将“代码/配置已确认”“实际运行记录已确认”“推断”“待确认”区分清楚。“完整”指覆盖可追踪的实验流程，不代表缺失信息已被补齐。未找到的设置写“未在所查材料中发现”，不要填入常见默认值。遇到配置与代码冲突，说明冲突及可能影响，不自行选择一个版本。若发现数据泄漏、测试集选模、指标口径不清等会改变结论的问题，单列为待核实项；报告任务本身不改变实验代码。

交付时给出报告路径、检查过的主要来源，以及无法从现有材料确认的内容。
