# M6 根据真实结果撰写 Markdown 报告

先读取用户提供或指定的结果：结构化文件、日志、图表、终端文本或消息中明确给出的数值都可作为来源。尽可能关联相应配置与运行记录，核对数据集、划分、评估阶段（训练/验证/测试）、指标定义、单位和方向；`run_id`、seed、代码版本、训练预算等信息有证据时记录，缺失时标为未知，不因此编造或拒绝整理。转录图片或文本中的数值时说明来源和精度限制。把 smoke test、合成数据、未完成运行与正式实验结果分开标识。

默认生成 `results/experiment_results_report.md`；若用户指定路径或项目已有报告约定，则遵从。报告至少包括结果范围及来源、能确认的指标定义与方向、按任务合适维度组织的 Markdown 结果表、主要观察和证据限制。表头应能看清方法或设置、数据集或划分、评估阶段、指标和数值；多运行场景在可获取时加 `run_id`、seed 或样本数。保留原始值和单位；如需四舍五入，说明规则。空缺写 `—` 并解释原因，不编造数值。

可以把不同协议下的真实结果列在报告中，但先区分“列示数值”与“比较性能”。只有指标口径、数据划分、候选集和评估协议足够明确且可比时，才计算跨方法差值、排名或相对提升；训练预算不同等限制应随比较说明。跨 seed 均值与标准差只能由实际多次独立运行计算，注明 `n` 和统计约定；单次运行直接报告原值。baseline、消融、最佳值和显著性等称谓与结论须有来源及对应协议。不可比或协议未知的结果分组列示或加注释，不作强结论。

结尾列出会影响解释的缺失记录与尚未核实的协议；只有用户需要复现实验时才补列所需信息。若完全没有数值，先请求结果材料，不生成空表或示例数值冒充报告。交付时给出报告路径和使用的来源，不声称已验证科研结论，除非相应证据确实齐全。
