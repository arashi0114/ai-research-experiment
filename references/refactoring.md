# M7 现有实验代码重构

先根据用户指出的问题确定重构范围，再阅读相关入口、配置、调用方与测试。识别这次修改可能触及的实验行为，例如数据划分与采样、预处理、模型计算、损失与优化、随机性、指标定义和选模规则。CLI 参数、导入路径、配置键、checkpoint `state_dict` 键和结果文件结构只有在被项目或外部调用方依赖时才需要特别核查；不要预设所有项目都必须保持这些接口原样。

先用简短计划说明拟改的文件、预期收益、要保持的行为以及已知兼容性要求，再在现有架构内做局部重构。优先解决实际的重复、复杂控制流或职责混乱；不要仅为“更通用”而加入注册器、工厂、多层管理器或第二套训练流程。用户要求改变接口或实验行为时可以修改，但须明确列出变化与迁移影响；不能把影响研究结论的修改称为等价整理。

按改动风险运行相关的已有测试；涉及数值或协议的改动，再用固定输入或现有 fixture 对照关键输出、指标、配置解析或 checkpoint 加载。只有触及训练路径时才需要最小训练步等较重检查。浮点差异按算法和设备合理解释，不要求跨硬件逐位相同。缺少依赖、数据或权重时，完成可执行的局部检查并列出无法验证的等价性；发现非预期不兼容时修复或清楚报告。

保留用户数据、权重、日志和结果。完成后报告代码结构变化、实测验证、尚未验证的风险，以及任何确实改变的接口或实验行为。
