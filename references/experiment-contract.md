# M3 实验契约

在编写正式实验代码前，建立 docs/experiment_contract.md，至少明确下列协议。逐项标注来源：用户已确定、无科研影响的工程默认值、需用户决定、暂不实现。不要把待定科研协议当作默认值。

1. 任务：目标、输入、输出、预测目标。
2. 数据：来源和版本、字段与格式、样本构造、训练/验证/测试划分及版本、预处理与归一化、潜在泄漏路径。
3. 模型：输入输出张量的 shape、dtype 和语义，模块组成，可训练/冻结参数，预训练权重来源、版本和加载方式。
4. 优化：损失、优化器、学习率及调度器、batch size、epoch、随机种子与重要超参数。
5. 评估：每项 metric 的数学或程序定义、方向、聚合方式、验证与测试用途、最佳 checkpoint 选择规则。

排序/推荐任务另明确候选集、负采样、过滤和排名口径；压缩任务另明确码率、失真、量化和熵编码口径；分类、分割、检测任务另明确类别、忽略标签与样本聚合方式。仅有 Recall@K、NDCG@K、Accuracy 等名称不足以决定所有实现细节。

若用户只说“帮我写训练和评估代码”，先询问任务输入/标签、数据划分、模型或预测目标、损失及评估定义等阻断事项；可以同时检查现有项目和建立待填契约，但不能编造指标或宣布闭环完成。普通工程默认值可自行决定并记录。缺少真实数据时可继续搭建已确定部分，明确未能实现或验证的部分。
